# F7 前端骨架与登录闭环

REQ-001 后端六个功能点(F1–F6)完成后,接口已经稳定,但它们只能通过 curl 触及。
本功能点建立前端工程骨架并打通登录闭环,是所有后续页面的地基。

## 1. 背景

- 后端已具备:注册、登录(签发 JWT)、鉴权过滤器、兴趣标签、收藏 / 阅读历史 / 评分,共 17 个接口,66 条测试全绿。
- 前端此前只有 Vite 脚手架(`App.vue` + `HelloWorld.vue`),无路由、无请求层、无 UI 库、无页面。
- 用户系统是"必须先登录才能用"的形态,所以登录闭环是前端的第一块砖:它决定路由结构、请求层与状态管理怎么做。

## 2. 目标

1. 建立可持续扩展的前端骨架:路由、请求层、登录态、布局。
2. 打通端到端闭环:注册 → 登录 → 刷新保持登录 → 访问受保护页 → 退出。
3. 统一错误处理:后端错误格式已统一,前端只写一套解析逻辑。
4. 建立前端测试设施(此前没有),让后续页面开发有回归网。

**不在本次范围**:兴趣选择器(FE-2)、收藏 / 历史 / 评分管理(FE-3)、检索 Agent(REQ-002)。

## 3. 系统设计

### 3.1 开发期如何连后端:Vite 代理,不配 CORS

前端代码只请求相对路径 `/api/**`,由 Vite dev server 转发到后端(默认 `localhost:8080`,
可用 `BACKEND_ORIGIN` 环境变量覆盖)。浏览器视角下前后端同源,**开发阶段完全不需要后端配置 CORS**。

后端 CORS 配置留到部署拓扑确定时再加:那时才知道前端是被 nginx 反代到同域,还是独立域名。
现在写只能填 `localhost` 猜一个,是一份无法验证的配置。

### 3.2 分层

```
views/          页面:登录、注册、首页
layouts/        登录后的外壳(顶栏 + 内容区),后续页面挂在它的 router-view 下
router/         路由表 + 登录守卫
stores/         登录态(token + 用户),localStorage 持久化
api/            client.js(axios 实例 + 拦截器)、auth.js(认证接口)
```

依赖方向单向向下:`views → api/stores`,`api/client → stores + router`,**下层不反向依赖视图**。
路由的页面组件一律懒加载,避免模块循环。

### 3.3 数据流:一次带鉴权的请求

```
视图调用 api/auth.js
  → axios 请求拦截器:从 stores/auth 取 token,加 Authorization: Bearer <token>
  → 请求经 Vite 代理转发到后端
  → 响应拦截器:
      成功       → 直接返回 body(视图不必再 .data)
      401        → 清登录态 + 跳登录页(若当前不在登录页)
      其它错误   → 归一化成 ApiError(message / status / fieldErrors)
```

**401 的一个例外**:登录接口自身凭据错误也返回 401,但那是"密码错了",不是"会话过期"。
所以拦截器对 `/auth/**` 的 401 不做登出跳转,只把消息交给登录页展示。

### 3.4 登录态存储

token 与用户信息一起存 localStorage,刷新页面不需要重新登录 —— 这是 SPA 的默认预期。
代价是 XSS 可读取;本项目没有把用户输入当 HTML 渲染的地方,当前可接受。将来若要收紧,
可换成后端下发 httpOnly Cookie + CSRF 防护。

存储内容损坏或被禁用时按未登录处理,不让白屏。

## 4. 核心流程

**注册**:填表 → 前端校验(与后端约束一致)→ `POST /api/auth/register` → 成功后
用同一份凭据 `POST /api/auth/login` 自动登录 → 进首页。
自动登录省掉一次手输;若自动登录意外失败,退回登录页并提示。

**登录**:填表 → `POST /api/auth/login` → 写入登录态 → 跳转 `?redirect=` 指定的页面(被守卫拦下的原目标),否则首页。

**刷新**:应用启动时从 localStorage 恢复登录态;首页挂载时请求 `GET /api/users/me`
回查一次 —— token 签名有效不等于用户仍然存在,这一步同时验证了 token 依旧可用。

**退出**:清登录态与存储 → 跳登录页。

**守卫**:未登录访问受保护页 → 去登录页并记住原目标;已登录访问登录/注册页 → 回首页。

## 5. 模块划分与文件

| 文件 | 职责 |
| ---- | ---- |
| `src/api/client.js` | axios 实例、请求/响应拦截器、`ApiError` 归一化、401 处置 |
| `src/api/auth.js` | 注册 / 登录 / 当前用户三个接口 |
| `src/stores/auth.js` | 登录态与持久化 |
| `src/router/index.js` | 路由表 + 全局守卫 |
| `src/layouts/AppLayout.vue` | 登录后外壳(品牌、当前用户、退出) |
| `src/views/LoginView.vue` | 登录页 |
| `src/views/RegisterView.vue` | 注册页 |
| `src/views/OverviewView.vue` | 首页:轻量概览(搜索框 + 三类行为统计 + 最近收藏 + 兴趣标签),只用本地数据、零外部调用 |
| `src/views/AccountView.vue` | 账号页:从顶栏用户名进入,不占导航位 |

## 6. 技术选型原因

| 选择 | 理由 |
| ---- | ---- |
| Element Plus | 表单校验、消息提示、容器布局开箱即用;后续推荐卡片流、对话页直接受益。与 Vue 3 同源,中文文档完善 |
| axios | 拦截器机制正好承载"注入 token + 统一错误"这两件事,比在每个调用点手写 fetch 包装干净 |
| vue-router | SPA 必需;守卫是登录闭环的落点 |
| **不用 Pinia** | 目前只有登录态一个模块,`reactive` 写个组合式 store 足够。等推荐 / 对话页带来更多共享状态再引入不迟 |
| **保持 JavaScript** | 脚手架是 JS;切 TypeScript 是独立的一件事,不混进本功能点 |
| Vitest + jsdom | 给请求层与登录态建回归网;也是后续组件测试的基础设施 |

## 7. 未来扩展

- **FE-3 收藏 / 阅读历史 / 评分**:同样挂 AppLayout 下。需要先有论文数据 —— 检索功能属 REQ-002,
