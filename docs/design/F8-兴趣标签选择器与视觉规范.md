# F8 兴趣标签选择器 + 全站视觉规范

FE-1 打通了登录闭环,但页面只是"能用",没有统一的视觉语言。本功能点做两件事:
定下全站视觉规范并落地为设计令牌,然后在其上实现兴趣标签选择器(FE-2)。

## 1. 背景

- 后端 F5 已提供兴趣标签能力:34 个标签分 6 类、权重 1–5、单用户上限 10 个,PUT 全量替换语义。
- 前端此前没有视觉规范:颜色、圆角、间距散落在各个 `.vue` 的 scoped 样式里,组件库还是默认观感。
- 用户要求:**简洁风格、蓝白为基调、可稍作装饰**。

## 2. 目标

1. 定一套可落地的视觉规范,以 CSS 自定义属性的形式集中管理,换肤只改令牌。
2. 让 Element Plus 组件库整体换色,而不是逐个组件打补丁。
3. 实现兴趣标签选择器:6 分类 / 34 标签 / 权重 1–5 / 上限 10,含未保存改动保护。

**不在本次范围**:收藏与历史管理(FE-3,需先有论文数据)、检索 Agent(REQ-002)。

## 3. 视觉规范

### 3.1 配色

全页只有**墨色三级 + 一个蓝**,层次由四级字号(13 / 15 / 18 / 22)、三级字重(400 / 500 / 600)
和留白承担,不靠阴影与色块。

| 令牌 | 值 | 用途与对比度 |
| ---- | ---- | ---- |
| `--pp-ink` | `#16181D` | 正文,白底 17.8:1 |
| `--pp-ink-2` | `#545C6B` | 次级文字,6.7:1 |
| `--pp-ink-3` | `#5F6F83` | 说明 / 占位符,5.1:1(AA 下沿,不得再浅) |
| `--pp-accent` | `#2563EB` | 唯一强调色,白底 5.2:1 |
| `--pp-accent-deep` | `#1E4FBC` | 浅蓝底上的文字,6.3:1;按钮 hover 底 |
| `--pp-bg-page` | `#F6F8FB` | 页面底色 |
| `--pp-line` | `#E8EAEF` | 分隔线 / 卡片描边 |

**为什么不用 Element Plus 默认的 `#409EFF`**:它白底只有 3.0:1,做正文链接和匹配分数不达标。
`#2563EB` 实测 5.17:1,仍然是"正经的蓝"。对比度一律以**最不利底色 `#F6F8FB`** 核算,而不是白色。

### 3.2 装饰预算

全站只有三处装饰,这是刻意的上限:

1. 品牌标记:一个 26×26 圆角方 + 脉冲折线 SVG(全站唯一图形标识)
2. 当前导航项的 2px 蓝下划线
3. 标签的 5 格权重刻度

登录页另有一层 6% 蓝的径向渐隐(55% 处消失)。**任何一处加重阴影或引入第二个彩色都会破坏整体感。**

### 3.3 与 Element Plus 共存

分两层:变量覆盖(改整体观感)+ 逐组件补丁(EP 表达不了的)。

**变量覆盖**写在 `frontend/src/styles/theme.css`,包括 `--el-color-primary` 系列
(light-3…9 按 EP 自身的混色规则预先算好写死,不现场手调)、圆角、字体、文字色、边框色、
组件尺寸与动效时长。

**必须逐组件补的 5 处**(缺一即"回默认 Element 味"):

1. `.el-input__wrapper` 的边框是 inset box-shadow,EP 的 focus 只有 1px,3px 外环必须自己叠
2. `.el-button--primary` 的 hover:EP 默认走 light-3 **变浅**,与本设计"hover 变深"相反
3. `.el-card` 默认带阴影,必须 `box-shadow: none`
4. `.el-form-item__label` / `.el-form-item__error` 的字号与间距
5. `el-form` 统一 `label-position="top"`

**一个必须处理的坑**:Element Plus 的样式是按需引入的,落在各路由的异步 chunk 里,
加载顺序**晚于** `theme.css`。同特异性时后者胜 —— 直接写 `:root` 会被组件库的默认值盖掉。
所以覆盖写成 `:root:root`、补丁写成 `:root .el-xxx`,把特异性提到 (0,2,0),与加载顺序解耦。

这不是多虑:构建产物里同时存在 `--el-color-primary:#2563eb`(我的)与 `#409eff`(EP 的),
靠的就是特异性而不是顺序。

## 4. 兴趣标签选择器

### 4.1 权重的三重编码

**不允许"只靠颜色"表达权重** —— 色觉障碍下会读不出强度。三条通道缺一不可:

| 通道 | 做法 |
| ---- | ---- |
| 文字色 | 五档共用同一个深蓝 `--pp-w-ink`(`#1E4FBC`),**绝不随权重变淡** |
| 底色 | w1 `#EDF2FE` → w5 `#C2D3F9`,描边同步加深,w4/w5 描边转实心 |
| 刻度 | chip 内 5 格,点亮格数 = 权重 |

亮格用 `--pp-accent-deep` 而非 `--pp-accent`,使亮 / 未亮格在五档底色上的对比达 3.09–3.89:1(≥3:1)。

### 4.2 交互

| 操作 | 效果 |
| ---- | ---- |
| 点标签本体 | 选中(默认权重 3)/ 取消 |
| 点标签内第 N 格 | 权重设为 N |
| ← → | 权重 −1 / +1 |
| Enter / Space | 切换选中 |

命中区扩到整个格距(4px 实条左右各外扩 1.5px),鼠标不必精确瞄 4px 宽的条。

### 4.3 上限反馈

上限是后端硬约束(超 10 个请求会被 `@Size(max=10)` 拦下,而且返回的是**笼统的「参数校验失败」**,
不是友好提示),所以界面必须自己拦住:

- 满 10 后未选标签降权(`opacity: .55` + `not-allowed`)
- 第 11 次点击不生效,但计数变红、右栏提示改写,约 1.8s 后复原
- **不用弹窗** —— 上限不是异常,但必须让用户知道刚才那下为什么没生效

### 4.4 保存按钮的启用条件

设计原稿写的是"选中数为 0 时禁用"。这有个漏洞:**用户把标签全清空后就再也保存不了了**,
页面卡在未保存状态。改为按"是否有未保存的改动"判断,并把 0 项时的文案改成「清空并保存」,
让"这次提交会清空"这件事在点之前就看得见。

## 5. 模块划分

| 文件 | 职责 |
| ---- | ---- |
| `src/styles/theme.css` | 设计令牌 + Element Plus 变量覆盖与组件补丁 |
| `src/styles/components.css` | 跨视图复用的类:品牌、卡片、链接、错误条、标签 chip 与刻度 |
| `src/composables/useInterestSelection.js` | 选择逻辑(上限 / 权重区间 / 重复),不依赖 DOM,可单测 |
| `src/api/interests.js` | 词表 / 我的兴趣 / 全量替换 |
| `src/components/BrandMark.vue`、`WeightTicks.vue`、`AuthShell.vue` | 复用组件 |
| `src/views/InterestView.vue` | 选择器页面 |
| `src/layouts/AppLayout.vue` | 顶栏外壳,导航项由路由表推导 |

## 6. 数据流

```
挂载 → 并行取 词表(GET /api/interests)与我的兴趣(GET /api/users/me/interests)
     → 用词表返回的 maxTags / minWeight / maxWeight 建选择引擎(限制由后端给,前端不写死)
     → 回填已选 → 记录快照

交互 → 只改本地状态 → isDirty = 当前序列化 ≠ 快照

保存 → PUT /api/users/me/interests(全量替换,载荷就是提交后的最终状态)
     → 用**服务端返回的列表**重绘(它会排序并过滤已下线的标签),而不是假定提交什么就是什么
     → 更新快照
```

**未保存保护**:有改动时离开路由会弹确认框。选标签是手工活,静默丢失最招人烦。

## 7. 错误处理

- **接口级错误用表单内的提示条,不用 `ElMessage` 浮层** —— 一次性的浮层提示容易被漏看,
  而且关了就没有了。错误条留在页面上,直到用户改动。
- 字段级错误贴到对应输入框下方,由后端 `fieldErrors` 回填。
- 加载失败不留白屏,页面上给出可读提示。
