# 技术选型与参考资料

本文件记录 PaperPulse 的技术选型决策、推荐模块的算法设计,以及可借鉴的开源项目。
需求清单见 [requirements.md](requirements.md),各功能点的实现细节见 [dev-log.md](dev-log.md) 与 [design/](design/)。

---

## 一、系统架构

`backend`(Java)负责用户与数据,`ai-service`(Python)负责 Agent / RAG / 推荐,两者通过 REST 通信;
`frontend`(Vue 3)面向用户,对话与推荐流走 SSE 流式输出。

```
┌───────────────┐   HTTP / SSE   ┌──────────────────────────────┐
│  Vue 3 前端    │ ─────────────▶ │  Java: Spring Boot 4.1        │
│  Element Plus │ ◀───────────── │  用户 / 鉴权(JWT + Security)   │
└───────────────┘                │  兴趣标签 / 收藏 / 历史 / 评分   │
                                 │  MySQL 8 + Spring Data JPA    │
                                 └──────────────┬───────────────┘
                                                │ REST API
                                 ┌──────────────▼───────────────┐
                                 │  Python: FastAPI 服务         │
                                 │  检索 Agent(工具调用循环)      │
                                 │  RAG(Chroma + BGE-M3)        │
                                 │  推荐引擎(embedding + LLM)    │
                                 │  对接 Semantic Scholar /      │
                                 │  Crossref / DeepSeek API      │
                                 └──────────────────────────────┘
```

## 二、技术选型

| 层 | 选型 | 说明 |
| ---- | ---- | ---- |
| 后端框架 | Spring Boot 4.1 / Java 21 | 实际已落地。用户系统为自研(未用脚手架),按功能分包 |
| 持久层 | Spring Data JPA + MySQL 8 | 开发环境复用本机 MySQL,`ddl-auto: update`;测试用独立库 `paperpulse_test` |
| 鉴权 | Spring Security + JWT | 无状态,过滤器解析 token;接口一律挂在 `/api/users/me` 下,用户取自 token 而非路径 |
| AI 服务 | FastAPI(Python 3.13) | Agent / RAG / 推荐的宿主 |
| LLM | DeepSeek API | OpenAI 兼容协议,成本低;预算紧张时可本地 Ollama + Qwen 小模型调试 |
| Embedding | BGE-M3(本地) | 免费、中文友好 |
| 向量库 | Chroma | 本地零配置 |
| Agent 循环 | 先用 LangChain 跑通,再考虑自写轻量循环 | 自写版能把"工具调用怎么转起来的"讲清楚 |
| 前端 | Vue 3 + Vite + Element Plus | 登录页、兴趣选择器、收藏管理页、对话页、推荐卡片流 |
| 部署 | Docker Compose 一键起 | 注意:本机 MySQL 已占 3306,启用 Docker 时须改为 `3307:3306` |

## 三、推荐模块的算法设计

做成"基线 vs. 进阶"两层,有对比实验才有说服力:

- **基线 1(传统)**:BGE 文本向量对论文标题+摘要做 embedding,用户兴趣向量 = 历史论文向量加权平均,
  cosine Top-K;可再加 TF-IDF / BM25 检索兜底。
- **基线 2(序列推荐)**:用 [RecBole](https://github.com/RUCAIBox/RecBole) 的 SASRec / GRU4Rec
  跑离线评测,作为传统序列推荐对比。
- **进阶(LLM 生成式推荐)**:把用户历史论文序列(标题+摘要的语义 token)喂给 LLM,
  让 LLM 从候选池中生成推荐**并同时生成推荐理由**,即 IDs → 语义的生成式路线。
- **可解释性(XAI)**:对比实验——"只给推荐" vs. "推荐 + 理由",记录点击率 / 收藏率差异,或做小规模问卷。
- **离线评测**:Recall@K、NDCG@K。用 arXiv 数据自建小数据集
  (用户 = 真实作者,"收藏" = 论文引用关系,这是学术界常用的 proxy,需在文档里说明该设定)。

## 四、可借鉴的开源项目

> **首选参考:[PaperAgent](https://github.com/happyTonakai/PaperAgent)**(Go + React,MIT)
> —— 论文精读 Q&A + 每日个性化推荐双系统,与本项目重合度最高。
> 它的"arXiv HTML/TeX 转 Markdown""锚点+动态截断""行为反馈闭环+探索位"三大设计直接可借鉴。

### 4.1 学术助手 / 论文阅读类

| 项目 | 亮点 | 借鉴点 |
| ---- | ---- | ---- |
| [gpt_academic](https://github.com/binary-husky/gpt_academic)(MIT) | 论文润色/翻译/总结、PDF 问答、插件化快捷按钮 | 功能清单规划、插件式设计、学术 prompt 写法。纯 Python Gradio,**学功能不抄架构** |
| [ChatPaper](https://github.com/kaixindelele/ChatPaper) | arXiv 批量抓取 → 结构化总结(背景/方法/实验/不足) | arXiv API 用法、批量处理管线、结构化总结 prompt |
| [paper-qa](https://github.com/Future-House/paper-qa)(MIT) | **带引用的高精度论文 RAG**:agentic 搜索 → 证据收集 → 生成答案 + 页码引用 | **精读问答模块最重要的参考**。学它的工具设计(PaperSearch / GatherEvidence / GenerateAnswer)与引用格式 |

### 4.2 论文推荐类

| 项目 | 亮点 | 借鉴点 |
| ---- | ---- | ---- |
| [arxiv-paper-crawler](https://github.com/Beil-z/arxiv-paper-crawler) | arXiv + 顶会抓取 → LLM 评分/筛选/翻译/总结 → 网页展示 | 最接近本项目的产品形态,学"抓取→打分→展示"整体管线 |
| [ArxivDigest-extra](https://github.com/linhkid/ArxivDigest-extra) | 两阶段筛选(快速过滤→精细分析)、相关度 1–10 打分 | 两阶段粗排+精排思路,可直接用到推荐模块 |
| [arxiv-tracker-agent](https://github.com/gaoweijun5/arxiv-tracker-agent) | LangGraph 工作流 + 混合 RAG(BM25+向量+RRF 重排)+ FastAPI/React | Agent 工作流编排与混合检索的工程实现 |
| [Awesome-RAG-Recommendation](https://github.com/Sjay-Wang/Awesome-RAG-Recommendation) | RAG × 推荐系统的论文清单 | 快速了解该细分方向的文献 |
| [ReasoningRec](https://github.com/millenniumbismay/reasoningrec)(arXiv:2410.23180) | LLM 生成可解释推荐,大模型生成理由微调小模型 | 可解释推荐的思路与实现 |

### 4.3 推荐算法库

- [RecBole](https://github.com/RUCAIBox/RecBole):标准推荐评测框架,SASRec / GRU4Rec 等开箱即用。
  用它做传统基线与 Recall@K / NDCG@K 评测,项目即从"工程 demo"升级为"有实验"。
